# Bearite

**Bearite** — лаунчер и загрузчик модов для **Super Bear Adventure** (Android, Unity IL2CPP) в духе Geode.
Оригинальную игру из магазина Bearite **не трогает и не удаляет**: он запускает её внутри себя
и подключает моды. Можно играть как обычно, а можно — с модами, без переустановки.

## Установка и запуск

1. Установи **Super Bear Adventure** из Google Play. Нужна версия, которую поддерживает Bearite
   (проверено на **13.0.8**).
2. Установи APK Bearite (артефакт `Bearite-debug` из сборки на GitHub, см. [Сборка](#сборка-из-исходников)).
3. Открой Bearite. На вкладке **Игра** должна быть зелёная отметка «Super Bear Adventure найдена».
4. Нажми **«Играть»**. Игра запустится в отдельном процессе, с подключёнными модами.

Bearite ищет игру по имени пакета `com.Earthkwak.Platformer`, а если его нет — по названию в
лаунчере. Если игра не найдена, на вкладке появится подсказка.

Вкладки Bearite:

| Вкладка | Что там |
|---|---|
| **Игра** | Статус игры, кнопка «Играть», сколько модов включено |
| **Моды** | Список установленных модов: включение, настройки, удаление, установка из zip |
| **Лог** | Журнал работы лаунчера и модов, кнопки «Обновить», «Копировать», «Очистить» |

## Как устроен лаунчер

Идея та же, что у Geode: лаунчер не меняет игру, а добавляет к ней свой код.

1. `GameActivity` (процесс `:game`) собирает загрузчик классов из APK игры (и её split-APK),
   нашего APK и папок с нативными библиотеками. Нативные библиотеки игры и Bearite оказываются в одном
   пространстве видимости, поэтому моды видят `libil2cpp.so`.
2. Всё, что игра спрашивает у `Context` (имя пакета, ресурсы, assets, путь к APK), отдаётся от имени игры.
   Системе отвечает настоящий лаунчер, поэтому Android не путает их.
3. Создаётся плеер Unity: `UnityPlayerForActivityOrService` (Unity 6) или `UnityPlayer` (старые версии).
4. Нативная библиотека `libbearite.so` ждёт, пока поднимется IL2CPP (10 секунд после загрузки),
   подключает свой поток, загружает бандлы и нативные библиотеки включённых модов.
5. Затем она следит за паузой (`Time.timeScale == 0`) и сообщает её Java. На паузе появляется кнопка
   **«Моды»**.
6. При выходе из игры процесс `:game` завершается. Лаунчер и оригинал остаются как были.

Конфиг для нативной части — файл `bearite_bundles.txt` в данных Bearite. Лаунчер пишет его перед каждым
запуском из текущего состояния модов.

## Мод-меню в игре

Открыть меню можно только на **паузе**: появляется жёлтая кнопка **«Моды»** сверху по центру.

- **Вкладка «Установлено»** — только включённые моды.
- **Вкладка «Все моды»** — все установленные моды, с поиском и фильтром:
  - поиск ищет по названию, id, автору и описанию;
  - фильтр: все, только включённые, только выключенные, с настройками, с нативным кодом.
- **Карточка мода**: аватарка, название, версия, автор и переключатель **«Вкл / Выкл»**.
  Если у мода есть описание или настройки, карточку можно раскрыть нажатием (стрелка `›`).
- **Настройки** применяются сразу. **Включение и выключение модов**, а также нативный код
  действуют **после перезапуска игры**.
- Закрыть меню: красный **X**, касание вне панели или кнопка «Назад».

## Встроенный мод Bearite

Как и в Geode, у лаунчера есть свой мод, и **ставить его не нужно**: он появляется в списке сразу после
установки Bearite и **включён по умолчанию**.

- Нативная библиотека `libbearite_mod.so` собирается вместе с лаунчером и лежит внутри APK.
- Его нельзя удалить, а подтверждать нативный код для него не нужно: это код самого Bearite.
- На карточке стоит пометка «встроенный». Выключить мод можно, как и любой другой.
- Он содержит **движок карт** (см. [Карты](#карты)): строит в игре объекты из вкладки «Карты».
  Если его выключить, карты не появляются.
- Id `bearite` зарезервирован: мод с таким id установить нельзя.

## Установка модов

Есть два способа.

**1. Через zip.** Вкладка **«Моды»** → кнопка **«Установить мод»** → выбери zip-архив.
Архив должен содержать `mod.json` в корне или в единственной папке.

**2. Вручную.** Положи папку мода в:

```
Android/data/com.bearite.patcher/files/mods/<id-мода>/
```

Папка должна содержать `mod.json` и всё остальное, на что он ссылается. Обновить мод можно, установив
новый zip: **настройки сохраняются**, нативный код придётся подтвердить заново.

**Безопасность.** Моды с нативным кодом (`libs`) выполняются внутри игры и имеют полный доступ к её
процессу. Они выключены по умолчанию. При первом включении Bearite попросит подтверждение.
Включай только те моды, которым доверяешь.

## Создание модов

### Быстрый старт

Всё для нативного мода лежит в папке [`sdk/`](sdk/): заголовки, скрипт сборки, шаблон и готовый мод
«Зум» (`sdk/sba-zoom/`). Брать что-то ещё из репозитория не нужно, а собирать мод можно прямо в браузере:

1. Создай папку `sdk/mods/мой-мод/` с файлами `mod.json` и `src/mod.c` (скопируй из `sdk/mods/template/`).
2. Сохрани. GitHub Actions соберёт все моды из `sdk/mods/`.
3. Вкладка **Actions** → последний запуск → **Artifacts** → `Bearite-mods` → zip твоего мода.
4. Bearite → **Моды** → **Установить мод**.

Подробно, с примером перехвата метода по имени: [`sdk/README.md`](sdk/README.md). Весь набор одним архивом
лежит в артефакте `Bearite-ModKit`.

### Структура мода

```
my-mod/
├── mod.json          ← обязательно: описание мода
├── icon.png          ← необязательно: аватарка (квадрат, например 128×128)
├── maps/
│   └── arena.bundle  ← бандлы Unity (если мод их использует)
└── libs/
    └── arm64-v8a/
        └── libmymod.so   ← нативная библиотека (если мод нативный)
```

Пути в `mod.json` всегда относительные, от папки мода. Ссылаться можно только на файлы **внутри** папки
мода: выход наружу (`../`) Bearite отклоняет.

Для zip: собери архив так, чтобы `mod.json` лежал в корне (`my-mod.zip/mod.json`) или в одной папке
(`my-mod.zip/my-mod/mod.json`).

### mod.json

```json
{
  "id": "my-mod",
  "name": "Мой мод",
  "version": "1.0",
  "author": "я",
  "description": "Что делает мод",
  "bundles": [ { "src": "maps/arena.bundle" } ],
  "libs":    [ "libs/arm64-v8a/libmymod.so" ],
  "settings": [
    { "id": "god",   "type": "bool",   "name": "Бессмертие", "default": false },
    { "id": "speed", "type": "float",  "name": "Скорость", "min": 0.5, "max": 3, "default": 1 },
    { "id": "lives", "type": "int",    "name": "Жизней", "min": 1, "max": 9, "default": 3 },
    { "id": "nick",  "type": "string", "name": "Ник", "default": "Bear" },
    { "id": "mode",  "type": "choice", "name": "Режим", "options": ["лёгкий", "обычный"], "default": "обычный" }
  ]
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `id` | да | Уникальный id: латиница, цифры, `_`, `-`, `.`. По нему хранятся настройки и включение |
| `name` | нет | Название в списке (по умолчанию = `id`) |
| `version` | нет | Версия, показывается на карточке |
| `author` | нет | Автор |
| `description` | нет | Описание, показывается в раскрытой карточке |
| `bundles` | нет | Список бандлов Unity: `{ "src": "путь" }` |
| `libs` | нет | Список нативных библиотек `.so` (только arm64-v8a) |
| `settings` | нет | Настройки, см. ниже |
| `hud` | нет | Кнопки на экране игры, см. [Кнопки на экране](#кнопки-на-экране-игры) |

Мод **без** `libs` включён сразу. Мод **с** `libs` выключен, пока пользователь его не подтвердит.

### Настройки

Настройки описываются в `mod.json` и рисуются в мод-меню сами. Типы:

| `type` | Как выглядит в меню | Значение |
|---|---|---|
| `bool` | переключатель «Вкл / Выкл» | `true` / `false` |
| `int` | «−» и «+» (если заданы `min` и `max`) или поле ввода | целое число |
| `float` | «−» и «+» (если заданы `min` и `max`) или поле ввода | дробное число |
| `string` | поле ввода | строка |
| `choice` | нажатием переключается по списку `options` | одна строка из списка |

- `description` — подпись под настройкой (не обязательна).
- `"control": "slider"` — для `int`/`float` с `min` и `max` в игровом меню рисует ползунок вместо «−» и «+».
- Значения хранятся в `settings.json` внутри папки мода. Bearite сохраняет их при обновлении мода.
- Нативный код читает настройки через SDK (функции `get_bool`, `get_int`, `get_float`, `get_string`).
  Значения подхватываются сразу, перезапуск не нужен.

**Если в `mod.json` нет `settings`**, в меню настроек не будет, а карточка без описания просто
переключает мод. Так сделан встроенный мод Bearite.

### Кнопки на экране игры

Мод может вывести кнопки прямо поверх игры, не заходя в настройки. Они описываются в `mod.json`
в массиве `hud` и **меняют настройки мода**; нативный код сразу читает новое значение.

```json
"settings": [
  { "id": "zoom_on",     "type": "bool",  "name": "Зум включён", "default": false },
  { "id": "zoom_amount", "type": "float", "name": "Сила зума", "min": 1.2, "max": 5, "default": 2 }
],
"hud": [
  { "label": "Зум", "setting": "zoom_on",     "action": "toggle", "pos": "left" },
  { "label": "+",   "setting": "zoom_amount", "action": "step", "step": 0.5,  "pos": "left" },
  { "label": "−",   "setting": "zoom_amount", "action": "step", "step": -0.5, "pos": "left" }
]
```

| Поле | Что значит |
|---|---|
| `setting` | id настройки из `settings`, которую меняет кнопка (обязательно) |
| `action` | `toggle` переключает `bool`, `step` прибавляет `step` к `int`/`float` (с учётом `min` и `max`), `cycle` листает `choice`. Если не указан, выбирается по типу настройки |
| `label` | Надпись на кнопке (по умолчанию название настройки) |
| `step` | Шаг для `step`, может быть отрицательным |
| `pos` | Где стоит кнопка: `left` (по умолчанию), `right`, `top-left`, `top-right`, `bottom-left`, `bottom-right`. Кнопки с одним `pos` выстраиваются столбиком |

Кнопки видны, пока игра идёт, и скрыты на паузе и в мод-меню. Они есть только у включённых модов.
Кнопка `toggle` горит зелёным, когда настройка включена, а после нажатия сверху на секунду показывается
новое значение.

### Аватарка icon.png

Чтобы у мода была своя аватарка, положи в корень папки мода, рядом с `mod.json`, файл **`icon.png`**:

```
my-mod/
├── mod.json
└── icon.png      ← имя ровно такое, маленькими буквами
```

- Формат PNG, лучше квадрат 128–256 пикселей (прямоугольную картинку обрежет по центру).
- Для zip-мода добавь файл в архив рядом с `mod.json` и поставь мод заново (настройки сохранятся).
- Для мода, который собирается в CI, положи `icon.png` в папку `sdk/mods/мой-мод/`: `build-mod.sh` кладёт его в zip.
- Если мод уже стоит, можно скопировать файл прямо в `Android/data/com.bearite.patcher/files/mods/<id>/`.
  На новых Android эта папка не открывается в большинстве файловых менеджеров, тогда проще переустановить zip.

Аватарка показывается в мод-меню в игре и на вкладке «Моды» в приложении. Без файла вместо неё
показывается первая буква названия на цветной плашке.

### Моды с бандлами (AssetBundle)

Бандл — файл, собранный в Unity (`AssetBundle`), с префабами, сценами или текстурами. Bearite загружает
бандлы через `UnityEngine.AssetBundle.LoadFromFile` и вызывает `LoadAllAssets`.

```json
"bundles": [ { "src": "maps/arena.bundle" } ]
```

Бандл должен быть собран **той же версией Unity**, что и игра (Unity 6 для Super Bear Adventure
версии 13.0.5). Иначе загрузка не удастся, и в логе появится строка «бандл не загрузился».

> **Важно.** Загрузка бандлов с нашего потока пока не проверена на устройстве. Если она не работает,
> смотри вкладку «Лог». Создание карт из ассетов игры (расстановка префабов по файлу описания карты)
> пока **не реализовано**.

### Нативные моды (.so) и SDK

Нативный мод — это arm64-v8a библиотека, которая экспортирует функцию:

```c
void bearite_mod_init(const BeariteApi* api, const char* mod_id);
```

Bearite вызывает её один раз после запуска IL2CPP игры. Через структуру `BeariteApi` мод получает:

| Функция | Что делает |
|---|---|
| `log(mod_id, text)` | Пишет строку в logcat (тег `Bearite`) и во вкладку «Лог» |
| `il2cpp_symbol(name)` | Адрес функции `il2cpp_*`, например `"il2cpp_class_from_name"` |
| `module_base(part)` | База загрузки библиотеки, в пути которой есть `part`, например `"libil2cpp.so"` |
| `hook(target, replacement, &original)` | Инлайн-хук (Dobby). Возвращает 0 при успехе |
| `get_bool / get_int / get_float / get_string` | Значения настроек мода |

Заголовки: `sdk/bearite_api.h` и `sdk/bearite_il2cpp.h`. Второй нужен, чтобы **перехватывать методы по имени**,
без адресов из дампа:

```c
bearite_hook_method(api, mod_id, "UnityEngine", "Camera", "set_fieldOfView", 1,
                    (void*)my_hook, (void**)&orig);
```

Готовые примеры:
- `sdk/mods/template/` — пустой мод, с него начинают (собирается в CI вместе со всем из `sdk/mods/`);
- `sdk/sba-zoom/` — «Зум»: хуки на `Camera.set_fieldOfView` и `Camera.get_main`, плавное приближение,
  кнопки «Зум», «+», «−» на экране и ползунки в мод-меню, в том числе «Центр зума по X/Y» (в какую точку
  экрана приближает; для этого сдвигается объектив камеры). Это отдельный мод со своей сборкой
  (`.github/workflows/build-zoom.yml`).

Правила для нативного кода:
- Строки от `get_string` действительны только до следующего вызова `get_string` в этом потоке. Копируй их сразу.
- Вызовы IL2CPP делай из потока, который Bearite выделил для модов (то есть из `bearite_mod_init`).
- Хуки ставь в `bearite_mod_init`.

## Если что-то не работает

1. Открой вкладку **«Лог»**. Там записаны стадии запуска: `libbearite загружена`, `libil2cpp загружена`,
   `домен IL2CPP готов`, `загрузка модов завершена`.
2. Если игра вылетела, при следующем открытии Bearite сам снимет **logcat** и добавит строки вокруг
   аварии (`Fatal signal`, backtrace, сообщения Unity). Это самая полезная часть.
3. Нажми **«Копировать»** и пришли текст из лога, если нужна помощь.

Частые случаи:
- **«Игра не найдена»** — установи Super Bear Adventure или проверь, что у неё тот же пакет.
- **Мод не появляется** — в `mod.json` ошибка, смотри строки «некорректный id» или «не удалось прочитать» в логе.
- **Мод с нативным кодом не работает** — проверь, что он включён и подтверждён, и что путь в `libs` верный.
- **Нет кнопки «Моды»** — она появляется на паузе. Если паузы в игре не видно, кнопка пока не появится.

## Сборка из исходников

APK собирает GitHub Actions (`.github/workflows/build.yml`), локальная сборка не нужна.

- Вкладка **Actions** → последний успешный запуск → **Artifacts**:
  - `Bearite-debug` — APK лаунчера;
  - `Bearite-mods` — готовые zip модов из `sdk/mods/` (сейчас шаблон);
  - `Bearite-ModKit` — набор для создания модов одним архивом.

Локально (если всё же нужно): NDK 26, `bash scripts/build_dobby.sh`, затем `gradle :app:assembleDebug`.
Dobby зафиксирован на коммите `6f065cf`.

## Карты

Вкладка **«Карты»** в меню Bearite (кнопка «Моды» на паузе) — редактор уровней прямо в игре.

**Что можно:**

- создать карту, добавить объекты: куб, шар, цилиндр, капсула, плоскость; готовые шаблоны (пол, лестница, арена);
- для каждого объекта: название, форма, позиция X/Y/Z, размер, поворот, цвет (12 цветов или свой RRGGBB),
  «твёрдый» (есть коллайдер) или нет; значения меняются ползунком, кнопками «−/+» или вводятся числом;
- для всей карты: сдвиг, масштаб, слой Unity, привязка к сцене (карта появляется только в ней);
- «Добавить объект перед камерой» и «К камере» ставят объект там, куда сейчас смотрит камера;
- «Поделиться» копирует карту текстом в буфер, «Из буфера» вставляет чужую карту;
- изменения видны в игре сразу, пока меню открыто или сразу после его закрытия.

**Как работает.** Карта — текстовый файл `maps/<id>.map` в данных Bearite. Встроенный мод читает эти файлы,
создаёт объекты через `GameObject.CreatePrimitive` на главном потоке Unity (тик берётся из хуков на
`Time.get_*`) и обновляет их при изменении файла. Состояние движка (сцена, камера, ошибки) мод пишет в
`maps/_state.txt`, оно показано сверху вкладки.

**Если карта не появляется:**

1. Сверху вкладки должно быть «Движок карт работает». Если там «вырезаны методы Unity», игра не содержит
   `GameObject.CreatePrimitive`; пришли текст вкладки «Лог» в лаунчере, там список доступных методов.
2. Проверь, что карта включена, а в поле «Сцена» стоит «Любая» (или нужная сцена).
3. Объекты создаются в точке «сдвиг карты + позиция». Если ты их не видишь, нажми «Сдвиг → к камере».
4. Если игрок проваливается сквозь твёрдый объект, поменяй «Слой»: у игры может быть своя схема слоёв.

## Ограничения и планы

- Работает только **arm64-v8a**.
- Сохранения, запущенные через Bearite, лежат в его данных и **отдельно** от оригинальной игры.
- Включение и выключение модов, а также нативный код применяются после перезапуска игры.
- Карты строятся из простых фигур Unity. Объекты из ассетов самой игры пока недоступны (есть только загрузка бандлов).
- Движок карт не проверен на устройстве; если игра вырезала нужные методы Unity, вкладка «Карты» покажет это.
- Не проверено на устройстве: загрузка бандлов с нашего потока, `dlopen` нативных модов и хуки Dobby
  в реальной игре.
- Проверки целостности и Google Play (лицензия, покупки) в самой игре не обходятся — это не цель проекта.

## Совместимость с версиями игры

Bearite не запускает сборки игры с защитой Google Play (Pairip, класс `com.pairip.application.Application`): такая сборка
проверяет лицензию под своим пакетом и закрывается при запуске из другого приложения. Лаунчер определяет её и показывает
понятное сообщение. Работает со сборками без этой защиты.

## Редактор карт

Вкладка «Карты» → карта → «Открыть редактор карты». Окно просмотра с сеткой и осями (X красная, Y зелёная, Z синяя),
манипуляторы «Двигать / Вращать / Размер», дерево сцены слева, инспектор справа, отмена и повтор, привязка к сетке.
Один палец по пустому месту вращает обзор, два пальца приближают и сдвигают, тап выбирает объект.

### Свои текстуры и отдельный мир

- **Текстуры.** В инспекторе объекта блок «Текстура»: «＋» берёт картинку из галереи (уменьшается до 512 px и хранится в `maps/textures/`), долгое нажатие удаляет. Цвет объекта работает как оттенок. Игре отдаются сырые RGBA-пиксели, поэтому она не должна содержать декодер картинок.
- **Отдельный мир.** Режим карты «Отдельный мир» (в файле `world=1`, `sky=RRGGBB`, `spx/spy/spz`): при включении карты рендереры и коллайдеры остального мира выключаются, игрок телепортируется на точку появления, небо заливается цветом карты. При выключении всё возвращается. Одновременно включён один мир; обычные карты в это время скрыты. Игрок ищется по тегу `Player` или по `CharacterController`; если в игре нет ни того ни другого, мир не включится (причина в логе).

### Круг телепорта

Форма «Круг телепорта» в редакторе карт (файл: форма `portal`, колонки `dest dx dy dz`). Куда ведёт: в точку этой же карты, на другую карту (отдельный мир включается сам, игрок встаёт на его точку появления) или «Выход в обычный мир». Круг срабатывает, когда игрок заходит в него; после телепорта нужно выйти из круга, чтобы он сработал снова. Дополнение к миру с кругом ведёт в свой мир, а круг внутри мира ведёт обратно.

**Родной круг игры.** В инспекторе круга есть раздел «Родной круг игры» (колонка `bind`, 22-я): имя объекта игры, который круг «занимает». Кнопка «Платформа Черепахограда» подставляет `Launch Platform (Turtletown)` — платформу, на которой в хабе запускается первый уровень. Пока карта включена, мод находит объект по имени, выключает у него скрипты и триггеры (игра перестаёт запускать уровень), прячет свой диск и телепортирует по настройкам круга: например, в отдельный мир. При выключении карты всё возвращается. Есть и второй режим — «Копия платформы»: мод делает копию платформы на месте круга (с кольцами и светом, но без скриптов), оригинал в хабе продолжает работать как раньше (колонка `clone`, 23-я). Так можно поставить «платформу запуска уровня» в любое место, в том числе внутри своего мира, и вести ею на свою карту. Что именно выключено, пишется в лог («родной круг … найден и занят»).
