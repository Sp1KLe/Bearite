# Bearite

Лаунчер модов для **Super Bear Adventure** (Android, IL2CPP) в духе Geode.
Игра **не удаляется и не перепаковывается**: Bearite — отдельное приложение,
которое берёт установленную из магазина игру, запускает её `UnityPlayer`
в своём процессе и подгружает моды.

## Как это работает
1. `GameActivity` собирает `PathClassLoader` из APK игры (и split-APK) + нашего APK.
2. Подменяет игре `Context`: имя пакета, ресурсы, assets, путь к APK. Системе отдаёт свои.
3. Через этот загрузчик грузится `libbearite.so`: ждёт IL2CPP, ставит хук (Dobby)
   на `il2cpp_runtime_invoke` и на потоке `UnityMain` грузит `AssetBundle` включённых модов.
4. Игра идёт в процессе `:game`; при выходе он убивается, лаунчер и оригинал остаются как были.

## Сборка
APK собирает GitHub Actions (`.github/workflows/build.yml`): вкладка Actions → артефакт `Bearite-debug`.
Локально: NDK 26, `bash scripts/build_dobby.sh`, затем `gradle :app:assembleDebug`.

## Моды
Zip с `mod.json` в корне (или в единственной папке). Ставится кнопкой в приложении
или кладётся в `Android/data/com.bearite.patcher/files/mods/<id>/`.
```json
{ "id": "my-mod", "name": "Мой мод", "version": "1.0", "author": "я",
  "bundles": [ { "src": "maps/arena.bundle" } ] }
```
Пример: `mods/example/`.

## Что не проверено на устройстве
Код собирается и компилируется, но на телефоне с настоящей игрой я его не запускал.
Рискованные места, если что-то не заработает (всё пишется в лог на главном экране):
- запуск `UnityPlayer` под чужим Context (зависит от версии Unity и от кастомного Application у игры);
- хук `il2cpp_runtime_invoke` и вызов `AssetBundle.LoadFromFile`;
- проверки целостности и Google Play (лицензия, покупки) в игре.

## Известные ограничения
- Сохранения лаунчерной копии лежат в данных Bearite и **отдельно** от оригинальной игры.
- Бандлы пока только загружаются; создание карт из ассетов игры (расстановка префабов) — следующий этап.
- Только arm64-v8a.
