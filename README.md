# Bearite

Неофициальный лаунчер для **Super Bear Adventure** с модами и своими картами. Оригинальная игра остаётся нетронутой: Bearite запускает её у себя и добавляет код модов.

- Свежий лаунчер: вкладка **Actions** → последний запуск **Build APK** → внизу **Artifacts** → `Bearite-debug` (скачается zip, внутри APK).
- В релизе [latest](https://github.com/Sp1KLe/Bearite/releases/tag/latest) лежат старые сборки `Bearite-debug.apk` и `Bearite-Mods.apk`: сборка их больше не обновляет.
- Приложение для отправки модов на сервер (`Bearite-Mods.apk`) собирается из папки `uploader/`; автоматической сборки у него сейчас нет.
- Нужна установленная игра из Google Play (проверено на версии 13.0.8) и телефон с arm64 или arm32 (armeabi-v7a): сборка универсальная.

## Лаунчер коротко

1. Установи APK, открой Bearite: на вкладке **Игра** должна гореть «Super Bear Adventure найдена».
2. **Играть** запускает игру с модами. Кнопка **Загрузить сохранение (.sba)** на той же вкладке подменяет сохранение игры (файл копируется как есть в `Android/data/com.bearite.patcher/files`, с тем же именем и расширением).
3. На паузе в игре появляется кнопка **Меню**: вкладка **Установлено** (все твои моды, выключенные полупрозрачные), **Все моды** (каталог с сервера, установка одной кнопкой), а также карты и мини-игры.
4. Вкладка **Лог** показывает, что происходит внутри; кнопка «Копировать» нужна, чтобы прислать лог при ошибке.

## Как сделать мод

Всё делается с телефона, в браузере. Компьютер и Android NDK не нужны: мод собирает GitHub в облаке.

### Что понадобится

- аккаунт на github.com (бесплатно);
- установленный Bearite и игра Super Bear Adventure;
- 10–15 минут.

### Шаг 1. Своя копия репозитория (один раз)

1. Открой репозиторий Bearite и нажми **Fork** → **Create fork**.
2. В своей копии открой вкладку **Actions** и, если спросит, нажми **I understand my workflows, go ahead and enable them**.
3. Добавь сборщик модов:
   - открой файл `sdk/github-workflow/build-mods.yml` и нажми «Copy raw file»;
   - **Add file → Create new file**, назови файл `.github/workflows/build-mods.yml`, вставь текст;
   - нажми **Commit changes**.

### Шаг 2. Папка мода

В своей копии создай папку `sdk/mods/мой-мод/` (**Add file → Create new file**; если в имени файла написать `/`, папки создадутся сами). В ней нужны:

```
sdk/mods/мой-мод/
├── mod.json        описание мода
├── src/mod.c       код мода на C
└── icon.png        (по желанию) аватарка, квадрат 128–256 px
```

Проще всего скопировать готовое из `sdk/mods/template/`: открой файл, «Copy raw file», вставь в новый.

#### mod.json

```json
{
  "id": "my-mod",
  "name": "Мой мод",
  "version": "1.0",
  "author": "я",
  "description": "Что делает мод",
  "libs": ["libs/arm64-v8a/libmymod.so"],
  "settings": [
    { "id": "speed", "type": "float", "name": "Скорость", "min": 0.5, "max": 3, "default": 1, "control": "slider" }
  ],
  "hud": [
    { "label": "+", "setting": "speed", "action": "step", "step": 0.5, "pos": "right" }
  ]
}
```

| Поле | Что значит |
|---|---|
| `id` | Обязательно. Латиница, цифры, `_`, `-`, `.`. По нему хранятся настройки; мод с тем же `id` при установке заменяется |
| `name`, `version`, `author`, `description` | Показываются на карточке мода |
| `libs` | Куда сборка положит библиотеку, например `libs/arm64-v8a/libmymod.so` (формат `lib<имя>.so`, только arm64-v8a) |
| `settings` | Настройки, меню рисует само |
| `hud` | Кнопки прямо на экране игры, они меняют настройки |

Типы настроек: `bool` (переключатель), `int` и `float` (кнопки «−/+» или ползунок при `"control": "slider"`, нужны `min` и `max`), `string` (поле), `choice` (список из `options`).
Действия кнопок `hud`: `toggle` (для `bool`), `step` (прибавляет `step` к числу), `cycle` (листает `choice`); `pos` — `left` или `right`.

#### src/mod.c

```c
#include "bearite_api.h"
#include "bearite_il2cpp.h"

__attribute__((visibility("default")))
void bearite_mod_init(const BeariteApi* api, const char* mod_id) {
    api->log(mod_id, "Привет из мода!");                  /* строка появится на вкладке «Лог» */
    double speed = api->get_float(mod_id, "speed", 1.0);  /* значение из настроек, обновляется на лету */
}
```

Через `api` доступны `log`, `get_bool / get_int / get_float / get_string` (настройки), `data_dir` (папка для своих файлов), `hook` и `il2cpp_symbol` (низкоуровневые хуки). Полный список с комментариями: `sdk/bearite_api.h`.

#### Перехват метода игры по имени

Самое частое, что нужно моду:

```c
static void (*orig)(void* self, float value, const void* method);

static void my_hook(void* self, float value, const void* method) {
    orig(self, value / 2.0f, method);            /* свой код, потом оригинал */
}

void bearite_mod_init(const BeariteApi* api, const char* mod_id) {
    if (!bearite_il2cpp_init(api)) return;
    bearite_hook_method(api, mod_id, "UnityEngine", "Camera", "set_fieldOfView", 1,
                        (void*)my_hook, (void**)&orig);
}
```

У метода экземпляра первым аргументом идёт `self`, последним всегда `const void* method`. Узнать имена классов и методов игры можно из лога: положи пустой файл `_dumpclasses` во внутреннюю папку `maps/` приложения, и при запуске игры вкладка **Лог** выведет классы и методы (подробности в `sdk/README.md`, раздел «Имена классов и методов из лога»). Готовый пример побольше: `sdk/sba-zoom/`.

### Шаг 3. Сборка

Нажми **Commit changes**. Сборка `Build mods` стартует сама. Следи на вкладке **Actions**: зелёная галочка значит готово, красная значит ошибка. Текст ошибки компилятора виден в разделе **Annotations** запуска и в логе шага «Build mods from sdk/mods».

### Шаг 4. Забрать мод

Actions → последний запуск → внизу **Artifacts** → `Bearite-mods`. Скачается zip, а в нём лежит `<id>.zip` твоего мода. Внешний архив распакуй: ставить нужно именно внутренний `<id>.zip`.

### Шаг 5. Поставить и проверить

1. Bearite → вкладка **Моды** → **Установить мод** → выбери `<id>.zip`.
2. Если у мода есть `libs`, он выключен, пока ты не включишь его в «Установлено» и не подтвердишь предупреждение про нативный код. Мод без `libs` включён сразу.
3. Запусти игру и открой вкладку **Лог**: строки `мод …` покажут, загрузился ли мод и сработал ли хук.

**Новая версия.** Подними `version` в `mod.json`, собери заново и поставь поверх. Настройки пользователя сохранятся.

**Поделиться со всеми.** Приложение `Bearite-Mods.apk` (исходники в `uploader/`) отправляет мод в релиз `user-mods` репозитория, и он появляется у всех во вкладке «Все моды». Для этого нужен токен GitHub: Settings → Developer settings → Fine-grained tokens, доступ только к твоему репозиторию, Permissions → Contents: **Read and write**. Токен хранится только в твоём приложении.

### Если не работает

| Что видно | Что делать |
|---|---|
| Сборка красная | Читай красную строку в Annotations: чаще всего опечатка в `mod.c` или в `libs` |
| Мод не появился в списке | В `mod.json` ошибка (нет `id`, лишняя запятая). Причина написана на вкладке «Лог» |
| Мод есть, но ничего не делает | Он выключен или не подтверждён. Смотри строки `мод …` в «Лог» после запуска игры |
| Хук не сработал | В «Лог» будет `перехват …: не найден`: проверь пространство имён, класс, метод и число аргументов |
| Игра вылетела | При следующем открытии Bearite сам добавит в лог строки из logcat про аварию; скопируй их |

### Чего не делать

- Не клади в репозиторий готовые APK и собранные файлы.
- Не заводи папку `releases`: сборка лаунчера нигде сама не публикуется, готовый APK лежит только в артефакте запуска **Build APK**.

Про аксессуары для гардероба читай ниже, а про звуки, достижения, мини-игры и сюжетные моды без кода — в разделе «Ещё немного».

*Инструкция написана для версии 1.2.0.*

## Как сделать аксессуар для гардероба

Аксессуар — это 3D-модель (шапка, очки, рюкзак, перчатки, ботинки…), которая надевается на твоего медведя в гардеробе. Он бесплатный, в одном слоте надет один аксессуар.

### Что понадобится

- готовая 3D-модель в формате **.glb** (сделать её можно в Blender, Blockbench или любом редакторе с экспортом в glb);
- аккаунт GitHub с правом загружать файлы в релиз `accessories` репозитория Bearite (для чужих аксессуаров — у владельца репозитория).

### Как всё устроено

Каждый аксессуар лежит в релизе `accessories` одним **.zip-архивом**. Внутри два файла:

```
my_hat.zip
├── index.json      описание: слот, смещение, размер, цвет
└── my_hat.glb      сама модель
```

Лаунчер при открытии каталога сам скачивает новые и изменённые архивы. Ничего собирать в GitHub Actions не нужно.

### Шаг 1. Подготовь модель

- Формат: `.glb`. Не больше **65 000 вершин**, но для аксессуара хватает нескольких сотен: чем проще, тем лучше. Файл лучше держать до 1–2 МБ.
- **Начало координат модели — это точка крепления.** Для шапки поставь его в основание (низ шапки), для очков — в центр, для рюкзака — в точку, которой он касается спины.
- Текстуру можно вшить прямо в `.glb` или положить в архив отдельным файлом `.png` (поле `texture`). Если текстуры нет, модель красится цветом из поля `color`.

### Шаг 2. Напиши index.json

```json
{"props":[{
  "id": "party_hat",
  "name": "Праздничный колпак",
  "author": "Sp1KLe",
  "model": "party_hat.glb",
  "slot": "head",
  "fit": true,
  "offset": [0, 0, 0],
  "scale": 1,
  "rot": [0, 0, 0],
  "color": "FFFFFF",
  "icon": "icon.png"
}]}
```

| Поле | Что значит |
|---|---|
| `id` | Латиница, цифры, `_`, `-`. По нему аксессуар запоминается; с тем же `id` он заменяется |
| `name` | Название в каталоге |
| `author` | Автор |
| `model` | Имя `.glb` внутри архива |
| `slot` | Куда надевается (см. ниже) |
| `fit` | Только для `head`: подгонка под форму головы (см. ниже). Необязательное, по умолчанию `false` |
| `offset` | Сдвиг `[x, y, z]` от точки крепления слота |
| `scale` | Размер: `1` — как в модели, `0.5` — вдвое меньше |
| `rot` | Поворот `[x, y, z]` в градусах |
| `color` | Цвет `RRGGBB`, работает, если у модели нет текстуры (`FFFFFF` — без изменения) |
| `texture` | Необязательно: `.png` внутри архива, если текстура не вшита в glb |
| `icon` | Необязательно: `.png` для карточки в каталоге |

В одном архиве можно держать несколько аксессуаров: клади их в массив `props`. Если аксессуар один, можно написать без обёртки, просто один объект.

#### Слоты

| Слот | Куда |
|---|---|
| `head` | голова |
| `face` | лицо (маски, очки) |
| `back` | спина |
| `body` | тело |
| `hand_l`, `hand_r` | левая и правая рука |
| `foot_l`, `foot_r` | левая и правая нога |

#### Подгонка под голову (`fit`)

У игры несколько форм головы (медведь, лис и другие), и размеры у них разные. Если в аксессуаре для `head` написать `"fit": true`, лаунчер сам измерит голову и посадит аксессуар на её верх, а при смене формы головы поправит положение. Тогда:

- `offset` считается **от верха головы**: нулевой `[0, 0, 0]` значит «модель стоит основанием прямо на голове»;
- начало координат модели должно быть в её основании (см. шаг 1).

Без `fit` аксессуар ставится в точку крепления головы со смещением `offset`, одинаковым для всех форм головы. Размер (`scale`) в обоих режимах задаётся вручную.

### Шаг 3. Собери архив

Положи `index.json` и `.glb` (и по желанию `icon.png` и `.png` текстуры) в один zip. С телефона это делается любым файловым менеджером: выдели файлы → **Сжать/Архивировать** → формат zip. Файлы должны лежать в архиве **в корне**, без лишней папки сверху (лаунчер найдёт и вложенные, но так надёжнее).

### Шаг 4. Загрузи в релиз

1. Открой репозиторий на GitHub → **Releases** → релиз `accessories` → **Edit**.
2. Перетащи свой `.zip` в список файлов (**Attach binaries**) и нажми **Update release**.
3. Файл заменяется, если у него то же имя: лаунчер заметит новый размер или дату и скачает его заново.

Другие релизы и папку `releases` в репозитории трогать и создавать не нужно.

### Шаг 5. Проверь в игре

1. Запусти игру через Bearite и зайди в гардероб.
2. Нажми кнопку-вешалку («Каталог»). Список обновится сам, новые аксессуары скачаются.
3. Выбери вкладку «Головной убор» (или подходящую) и нажми на свой аксессуар: он станет «Надето».
4. Не там стоит? Поправь `offset`, `scale` или `rot` в `index.json`, замени zip в релизе и обнови каталог.

### Если не работает

| Что видно | Что делать |
|---|---|
| В каталоге пусто | Проверь, что в релизе `accessories` лежит именно `.zip`, а не просто `.glb` |
| «Релиз недоступен» | Нет интернета или релиз не опубликован (это не черновик) |
| Аксессуар есть, но на медведе его нет | Открой вкладку «Лог» в лаунчере и найди строки «гардероб: …». Причина обычно там |
| Аксессуар слишком большой или маленький | Измени `scale` |
| Висит в воздухе или в голове | Измени `offset`; для шапок включи `"fit": true` и поставь начало координат модели в её основание |
| «слишком сложная модель» | В модели больше 65 000 вершин, упрости её |
| Цвет не меняется | У модели есть текстура, `color` работает только без неё |

*Инструкция написана для версии 1.2.0.*

## Ещё немного

- **Карты.** Вкладка «Карты» в меню на паузе: редактор своих карт из примитивов, импорт из буфера (`BEARITE-MAP`), свой мир со своим названием и обложкой, круг-вход в игровом стиле.
- **Мини-игры.** В меню на паузе: паркур-гонка, царь горы и догонялки на специальных аренах. Запускает хост комнаты. Ник для мультиплеера задаётся на главной странице лаунчера; комнаты создаёт и принимает сама игра (до 4 игроков — такой лимит у её сервера).
- **Чат.** Кнопка 💬 поверх игры, работает в комнате мультиплеера (общий публичный ntfy.sh); окно двигается и меняется в размере.

### Звуки и песни в модах

Положи звук в папку мода (`sounds/win.ogg`, подойдут wav, ogg, mp3, m4a) — он поедет в том же zip. В коде мода:

```c
if (api->play_sound) api->play_sound(mod_id, "sounds/win.ogg", 1.0f, 0);   /* громкость 0..1, 0 = один раз */
if (api->play_sound) api->play_sound(mod_id, "sounds/theme.mp3", 0.6f, 1); /* песня по кругу */
if (api->stop_sound) api->stop_sound(mod_id, "sounds/theme.mp3");          /* NULL — остановить всё */
```

Проиграть можно в любой момент: сделал действие (сработал твой хук, нажата кнопка `hud`, настройка поменялась) — и звучит. Файлы берутся только из папки мода.

### Пропы и монета в редакторе карт

В окне «Добавить объект»: вкладка «Фигуры и предметы» (там же **Монета**: собранная монета исчезает и запоминается, счётчик сверху экрана), «Игра» (модели из игры) и «Сообщество» (свои `.glb`, магазин, импорт `.zip` с `index.json`).

### Мини-игры в редакторе карт

В настройках карты (редактор, пункт «Карта») раздел **Мини-игра**: цель (собрать все монеты / дойти до финиша / и то и другое), лимит времени и тексты победы и поражения. Расставь на карте **Монеты** и **Финиш** (вкладка «Фигуры и предметы»). Время начинается, когда игрок отходит от точки старта; вверху экрана показываются таймер и монеты. После победы или поражения игрок возвращается на старт, монеты появляются снова.

### Метки объектов (мини-игры пишет мод)

У каждого объекта в редакторе есть поле «Метка» (например `start`, `finish`, `checkpoint`, `coin`). Мод сам находит такие объекты и решает, что с ними делать:

```c
if (api->tag_count) {
    int n = api->tag_count("checkpoint");
    for (int i = 0; i < n; i++) {
        float pos[3], size[3];
        if (api->tag_get("checkpoint", i, pos, size)) { /* позиция и размер в мире игры */ }
    }
    api->tag_set_visible("coin", 0, 0);   /* спрятать первую монету; index < 0 — все */
}
```

Вызывай из игрового потока (из своих хуков). Правила, таймер, победа — код мода; редактор только расставляет объекты.

### Свои достижения

В `mod.json`: `"achievements": [{"id":"first_coin","name":"Первая монета","desc":"Подбери монету"}]`. В коде мода: `if (api->unlock_achievement) api->unlock_achievement(mod_id, "first_coin");` — игрок увидит уведомление, а список появится в паузе по кнопке «Достижения» (она открывает наше окно, не окно Google Play). Повторный вызов ничего не делает; открыть можно только то, что описано в `mod.json`.

### Сюжетные моды без кода

Мод может состоять только из `mod.json`, звуков и карт — C-код и сборка не нужны.

- Кнопки на экране игры без настроек:
  ```json
  "hud": [
    { "label": "♪", "action": "sound", "file": "sounds/theme.mp3", "volume": 0.6, "loop": true, "pos": "right" },
    { "label": "?", "action": "say", "text": "Найди три монеты и дойди до флага", "pos": "right" }
  ]
  ```
  `sound` играет файл из папки мода (при `loop` второе нажатие останавливает), `say` показывает текст.
- Карты в архиве: положи `maps/<имя>.txt` (текст из «Скопировать карту», он начинается с `BEARITE-MAP`). При установке мода карты появятся во вкладке «Карты»; при переустановке заменятся. Мини-игру, монеты и финиш задай в самой карте.
- Свои пропы: `.zip` с `index.json` и `.glb`. Если в модели есть анимация, при добавлении в карту она ставится как ключевые кадры (двигается вся модель целиком, анимация одного узла).

### Имена методов из лога

Дампер можно не использовать: если во внутренней папке приложения `maps/` лежит пустой файл `_dumpclasses`, при запуске игры вкладка **Лог** пишет классы и методы игры (строки `разведка классов`, `класс …`; по умолчанию выключено). Как их читать и использовать, написано в `sdk/README.md`, раздел «Имена классов и методов из лога».

## Сборка из исходников

Любой пуш собирает APK через GitHub Actions (`.github/workflows/build.yml`): готовый файл лежит в артефакте `Bearite-debug` запуска. Релизы `latest` и `mods` сборка не трогает. Каталог модов (релиз `mods`) пополняется вручную: zip мода и `index.json` кладутся в релиз. Мод «Зум» собирает отдельный воркфлоу `build-zoom.yml` (артефакт `sba-zoom`). Если в корне лежит файл `RELEASE_ZZZ`, сборка ещё выкладывает временный релиз `Zzz`, а файл `DELETE_ZZZ` его удаляет. Локально нужны Android Studio, Gradle 8.x (в облаке 8.14.3; Gradle 9 не подходит к текущему плагину Android), NDK 26.1 и CMake 3.22, а перед первой сборкой `scripts/build_dobby.sh` (хуки).

Устройство лаунчера: `GameActivity` в отдельном процессе `:game` собирает загрузчик классов из APK игры и запускает Unity; нативная `libbearite.so` ждёт IL2CPP и подключает моды, встроенный мод `libbearite_mod.so` отвечает за карты, мини-игры и окно уровня.
